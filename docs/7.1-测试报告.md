# PayMerge-PDF 7.1 测试报告

日期：2026-11-20。开发、依赖缓存、交叉编译和 PDF 核心验证在 Linux 服务器的项目目录完成；Windows 仅从映射盘运行生成的 EXE，没有安装新的 Windows 编译环境。

## 本次变更

原生 Rust 界面改为深色侧栏、浅色工作区、三份材料卡片、独立核对区及固定输出操作区。配置窗口、中文字体字重、输入框、版本入口和程序图标同步调整。PDF 识别、合成版式和命名规则沿用 7.0。

新增 GitHub Releases 检查、校验下载、独立 Rust 升级进程、替换失败回滚和暂存目录清理。启动时和运行期间每 6 小时检查，支持手动检查；下载和重启升级由使用者点击确认。升级不会修改个人配置或输出 PDF。

| 原生升级回滚 | 故意指定不匹配的安装版本，启动校验失败后恢复原 EXE；配置和模拟输出文件逐字节一致 |

Windows 原生升级验收使用不启动交互界面的安装方式，真实运行独立升级 EXE 和新版的版本/PDFium 校验入口，并调用升级后的清理入口；没有自动点击“重启并升级”按钮。原生文件对话框、系统拖放与弹窗按钮没有进行桌面自动化操作，对应业务状态入口和返回映射已覆盖测试及代码检查。所有本次测试均未使用 Computer Use、鼠标键盘注入或桌面截图。

## 正式发布后的在线复验

Rust 源码已推送至 [public 仓库](https://github.com/ZhangStudyLife/PayMerge-PDF)，[v7.1.0 正式 Release](https://github.com/ZhangStudyLife/PayMerge-PDF/releases/tag/v7.1.0) 已上传完整 Windows x64 ZIP 与校验文件。GitHub 生成的包摘要与本地包核验记录一致。

使用 Windows 原生 Rust 验收程序，通过正式客户端的检查、下载和安装接口，完成以下验证：

1. 以旧版本号检查，正确发现 v7.1.0，读取本仓库正式发布的安装包和 GitHub SHA256。
2. 从 GitHub 完整下载并逐项校验，启动独立升级器替换真实 EXE/DLL；新版版本及 PDFium 加载校验成功。
3. 再次从 GitHub 下载，故意指定不匹配的安装版本；启动校验失败后，旧 EXE/DLL 恢复，个人配置及模拟输出 PDF 保持一致。
4. 以当前 7.1.0 检查，正确返回无需升级；两次升级暂存目录均已清理。

在线复验期间遇到过代理 EOF 和下载连接中断，保留了明确的失败结果；最终使用原有普通网络路径完整复验通过，没有修改系统代理配置。全部隔离的合成 PDF、截图、临时配置、程序复制件及临时测试通道已清理。机器可读汇总见 [验收记录](7.1-validation.json)。
